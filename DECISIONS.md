# Решения владельца и ограничения

Согласовано: современный минимализм ВГТК, комбинированная навигация, поиск/избранное/недавние/незаполненные занятия, Excel-редактирование, модальное окно занятия, три статуса работ, аналитика куратора, мобильный кабинет учащегося с локальными уведомлениями и PWA, постепенный рефакторинг, будущий API. Расписание только сегодня/завтра; парсер отдельно. Дизайн — на текущей палитре и темах.

## Требуют подтверждения (рекомендации, не утверждённые правила)
- D1. Подгруппы: сохранять существующее редактирование чужой подгруппы только с явным подтверждением и метаданными, либо запретить? Предлагается сохранить существующее поведение прототипа до решения; для массовых операций по умолчанию чужие ячейки исключить. Уточнить отдельно права на общие лекции и работы. README и код расходятся.
- D2. Оценки: 1–10, Н, пустая ячейка; нужен ли 0, зачёт/незачёт, иные обозначения? Предлагается разрешить только подтверждённый набор, не удалять старые неизвестные значения. Пустая ячейка не означает присутствие.
- D3. Завершённость: предлагается явный статус занятия (черновик/завершено) для конкретного листа/ответственного, а не вывод из пустых оценок. Для существующих занятий без статуса — «не определено», без массового автозавершения. Присутствие без отметки не должно требовать оценки. Уточнить, нужно ли отмечать присутствующих явно и обязательна ли тема.
- D4. Учебные периоды: предлагается конфигурируемый учебный год и границы семестров по календарю колледжа; до получения дат — только месяц, весь период, произвольный диапазон; старые DD.MM из демо — 2026, старые записи пользователя без года требуют подтверждения. Уточнить правила для старых ключей причин вида studentId_day: не угадывать месяц; сохранить и показать как нераспределённые до ручной привязки.
- D5. Работы: предлагается NOT_SUBMITTED / SUBMITTED / REVISION; только SUBMITTED считается выполненной, REVISION — в списке работ к доработке. Без даты сдачи не называть несданные работы просроченными. Уточнить, нужно ли отличать «ещё не задано» от «не сдано»; если да, нужен отдельный признак назначения (вне трёх статусов).
- D6. Куратор: оставить текущие пороги (Н/У >=4 часа или средний балл <5 при наличии оценок) как настраиваемые значения по умолчанию; уточнить период, допустимые причины и полномочия ручных корректировок, а также способ расчёта среднего (среднее индивидуальных средних или по всем оценкам). Процент посещаемости не считать из одних Н и отметок без знаменателя. Предлагается показывать абсолютные часы и уточнение причин, сохраняя текущий формат .doc.
- D7. Привязка расписания: будущий источник должен возвращать дату ISO, группу, предмет, слоты, преподавателя, аудиторию и стабильный идентификатор/правила сопоставления. Предлагается не создавать занятия автоматически из расписания; при неоднозначности предложить ручной выбор. Уточнить, когда считать занятие незаполненным при отсутствии записи в журнале. Пока расписание демо, дата не соответствует текущему дню; не показывать ложное «сейчас».
- D8. Уведомления/PWA: локальная лента изменений, без push и фоновой доставки; при первом входе существующие оценки не считать новыми. Кэшировать только статические ресурсы приложения; не кэшировать персональные данные/API. Оффлайн-редактирование и синхронизация отложены. Публичный пилот с реальными данными только после серверной авторизации, прав и защиты данных.
