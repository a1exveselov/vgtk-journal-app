# Общий чек-лист приёмки владельцем

1. Зафиксировать до задачи исходное `git status --short`, проверить незакоммиченные изменения; работать в отдельной ветке после сохранения текущего состояния. Не делать reset/clean автоматически.
2. Запускать только одну задачу. После неё проверить список изменённых/созданных файлов против W/N, diff, отчёт проверок. Не принимать задачу со скрытым расширением области или непроверенной миграцией.
3. Регрессия на копии демонстрационных данных: 1/2 часа, Н=1 час, оценка 10, удаление оценки, чужая подгруппа по утверждённому правилу, тема/ДЗ, ЛАБ/ПР, кураторская причина и экспорт, личный кабинет. Не тестировать на единственной копии настоящих данных.
4. Для данных: пустые значения, повреждённый JSON, повторная миграция, две группы с одинаковым предметом, 24.10/24.11, переход года, февраль, отказ сохранения, отсутствие оценки. Старые данные не исчезают.
5. Для UI: 360/390/768/1280/1920, обе темы, клавиатура, focus-visible, модалка/Escape, пустые состояния, локальная прокрутка таблицы. Проверить визуально; сборка не заменяет ручную приёмку.
6. Если всё прошло — владелец принимает и фиксирует изменения в Git. Только после этого следующая зависимая задача. При ошибке — отдельная короткая задача на исправление, не смешивать с новой функцией.
